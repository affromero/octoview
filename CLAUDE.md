# octoview — project instructions

Safari/Chrome/Firefox MV3 extension that renders ML and data files inline on
GitHub blob pages. `extension/` is the Safari source of truth; Chrome and
Firefox variants are generated by `scripts/build-chrome.mjs` /
`scripts/build-firefox.mjs` (never edit `build/`).

## README must follow the code — every structural change

The README is the product page AND the architecture doc. When a change touches
any of the following, update the README in the SAME commit or branch:

- **Architecture Mermaid diagram** (`## How it works → ### Architecture`):
  new/renamed/removed extension files, new viewer pages, changed message flows
  (postMessage handshakes, fallbacks), new build variants, or changed
  per-browser CSP behavior.
- **Format support table** (`## What it previews`): any renderer or decoder
  added/promoted/removed — keep the Status column truthful (✅ only with a
  passing WebKit e2e case).
- **Browser table + footnote** (`## Related work`): capability differences
  between Safari/Chrome/Firefox.
- **Screenshots** (`assets/screenshots/`, collapsible section): regenerate via
  `npm run screenshots` when the pane UI visibly changes.

## Commands

- `npm run ci` — lint + format check + vitest (the commit gate)
- `npm run test:e2e` — every sample rendered in Chromium AND WebKit (the
  Safari-truth harness; a format is only "supported" when it passes here)
- `npm run test:chrome` — Chrome build loaded into real Chromium (extension
  origin paths: button, live report, splat fallback)
- `npm run test:firefox` — Firefox build + addons-linter (AMO's validator;
  `web-ext` crashes natively on this machine, use addons-linter)
- `./scripts/build-safari.sh` — signed Mac App Store archive

## Constraints that keep biting

- Chrome/Firefox reject `'unsafe-inline'` and `blob:` in extension_pages CSP
  outright (whole extension fails to load) — Safari needs both. Never merge the
  manifests; patch per-variant in the build scripts.
- Firefox: no manifest `sandbox` key, no blob workers (WONTFIX) — live reports
  fall back to static, splats to the main-thread renderer. Don't ship Spark
  bundles to Firefox (addons-linter FILE_TOO_LARGE at >5MB).
- Decoders live in `extension/splat-decode.js` and stay pure (no DOM, no
  browser.*) so vitest covers them; renderer contract is
  `{ count, pos, col, size }`.
- `core.js` stays free of `browser.*` for the same reason.
